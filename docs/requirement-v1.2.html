1. Konteks Proyek: Satu CMS, Banyak Modul

Yang dibangun adalah SGA CMS — satu platform backend terpadu yang menjadi pusat kendali seluruh konten Landing Page SGA. Fitur dikemas sebagai modul yang dibangun dan dirilis bertahap:

ModulMengelolaStatus
Advocation (service terpisah, sudah live) Student Voice — form pengaduan/aspirasi mahasiswa Sudah live
Student Event — dokumen ini Event mahasiswa, kalender, runsheet, Google Calendar Modul pertama
Modul berikutnya (kandidat) UKM / Student Societies, profil pengurus, pengumuman/news, konten section LP (hero, about, vision) Menyusul
Implikasi arsitektur (wajib dibaca BE): jangan membangun "aplikasi event" yang berdiri sendiri. Bangun kerangka CMS — auth admin, struktur response, konfigurasi modul, upload media — yang modul Student Event menjadi penghuni pertamanya. Modul berikutnya hanya menambah resource baru, bukan service baru. Keputusan di dokumen ini wajib mempertimbangkan modul-modul berikutnya.

1.1 Masalah yang diselesaikan

Section Event & Kegiatan di landing page saat ini ditulis manual di dalam kode (src/components/sections/event/index.tsx): 6 kartu event placeholder, status "On Going" diketik manual, tidak terhubung ke data mana pun. Akibatnya:

  • Ganti event = edit kode + deploy ulang.
  • Status event (berlangsung / akan datang / selesai) tidak pernah akurat.
  • Mahasiswa tidak punya satu tempat melihat seluruh jadwal event.
  • Publikasi event tidak bisa lewat link — harus screenshot/manual.

Solusi: portal event mahasiswa (/events) dengan data dari SGA CMS, plus sinkronisasi ke Google Calendar.

Prinsip: CMS = sumber data tunggal. Google Calendar = turunan (one-way push). Status berlangsung/akan datang/selesai selalu dihitung otomatis dari waktu mulai–selesai, tidak pernah diinput admin.

2. User Flow

2.1 Flow Admin (mengelola event)

1 Admin login ke panel SGA CMS.
2 Masuk modul Student Event → daftar event (judul, tanggal, status publish, jumlah sesi).
3 Klik "Buat Event" → isi form: judul, slug (auto dari judul, bisa diedit), deskripsi, cover, tanggal & jam mulai–selesai, lokasi (+link), registration URL (opsional), penyelenggara.
4 Tambah sesi (runsheet): nama sesi, jam mulai–selesai, pemateri, ruang — berapa pun, bisa disusun ulang (drag order atau tombol naik/turun).
5 Simpan sebagai Draft → preview tidak muncul di publik.
6 Klik Publish → event muncul di endpoint publik; (fase 2) otomatis ter-push ke Google Calendar.
7 Edit ulang kapan saja — perubahan langsung terlihat di portal tanpa deploy ulang.

2.2 Flow Mahasiswa (konsumen)

1 Masuk lewat share link (WA/IG) → halaman detail event /events/:slug: cover, deskripsi, lokasi, runsheet per jam.
2 Atau masuk dari landing page → section Event (teaser carousel) → klik "Lihat Lainnya" → portal /events.
3 Di portal: lihat card besar "Sedang Berlangsung" (dengan sesi yang sedang jalan + jam), scroll ke "Akan Datang", atau eksplor via kalender bulanan.
4 Klik tanggal di kalender → muncul daftar event tanggal itu (jam per sesi). Klik event → detail.
5 Di detail: klik "Daftar" (jika ada), "Tambah ke Google Calendar", atau "Bagikan" (share lagi ke teman — loop viral).
6 (Fase 2) Mahasiswa bisa subscribe kalender publik SGA sekali → semua event baru otomatis masuk Google Calendar pribadinya.

3.2 Detail endpoint publik

GET /api/v1/events

  • Query: status (upcoming|ongoing|past, wajib salah satu — tanpa filter berarti semua published), limit (default 12, max 50), page (default 1).
  • Response data: array event ringkas + meta pagination ({ current_page, total, per_page }).
  • Sortir: upcoming → starts_at terdekat dulu; past → terbaru dulu; ongoing di atas semuanya.
  • Hanya event published yang muncul.
  • Field ringkas list: slug, title, cover_image_url, starts_at, ends_at, location, organizer — tanpa sessions (hemat payload; sesi hanya di detail).

GET /api/v1/events/:slug

  • Detail lengkap + sessions[] urut starts_at naik.
  • 404 dengan { "success": false, "message": "..." } jika slug tidak ada / masih draft.

GET /api/v1/events/calendar?month=YYYY-MM

  • Event yang irisan rentangnya dengan bulan tsb (event multi-hari yang menyentuh bulan itu tetap masuk).
  • Response ringkas per event: slug, title, starts_at, ends_at, location — FE yang mengelompokkan per tanggal, server tidak perlu group.
  • Default bulan sekarang jika month tidak dikirim.
Aturan wajib: status ongoing / upcoming / past dihitung server dari starts_at / ends_at dibanding waktu sekarang (timezone Asia/Jakarta). Bukan kolom yang diisi admin. Logika: ongoing jika now ≥ starts_at dan now ≤ ends_at; upcoming jika now < starts_at; past jika now > ends_at.

3.5 Admin panel (di SGA CMS)

  • Login (satu auth untuk seluruh CMS — modul berikutnya memakai yang sama).
  • Daftar event: kolom judul, tanggal, status publish, jumlah sesi; filter status; search judul.
  • Form event: field §3.3 + editor sesi (tambah/hapus/urutkan, inline).
  • Upload cover (preview sebelum simpan).
  • Publish / unpublish — satu klik, konfirmasi.
  • Pratinjau share link (/events/:slug) + tombol copy.

3.6 Google Calendar

  • Fase 1 (frontend saja, tanpa backend): tombol "Tambah ke Google Calendar" memakai template URL resmi https://calendar.google.com/calendar/render?action=TEMPLATE&text=...&dates=...&location=.... Tanpa API, tanpa OAuth. Tidak ada kerjaan BE di fase ini.
  • Fase 2 (backend): saat event di-publish, CMS push ke satu kalender publik SGA via service account (create/update/cancel event ikut status CMS). Prasyarat: GCP project, enable Calendar API, service account JSON, kalender publik di-share ke SA. Mahasiswa subscribe kalender SGA sekali, semua event masuk otomatis.

4. Frontend — Landing Page SGA

4.1 Route baru

RouteIsi
/eventsPortal event (hero, ongoing, upcoming, kalender)
/events/:slugDetail event — target dari share link

Frontend tidak menunggu backend selesai: buat dummy JSON sesuai contract §3, lalu tinggal ganti base URL saat CMS siap.

4.2 Struktur halaman /events

  1. Hero — judul + deskripsi (dari endpoint settings, fallback teks statis).
  2. Sedang Berlangsung — kartu besar prioritas: judul, sesi yang sedang jalan + jam ("Sekarang: Seminar Teknis, 13.00–15.00"), lokasi, CTA "Lihat Detail" dan "Daftar".
  3. Akan Datang — grid kartu. Desain memakai ulang kartu event yang sekarang ada di landing page, tinggal di-dinamisasi.
  4. Kalender bulanan — grid bulan custom (± 150 baris, tanpa library FullCalendar): titik/penanda di tanggal ber-event, klik tanggal → daftar event tanggal itu lengkap jam per sesi, klik event → halaman detail. Di mobile tampilkan sebagai agenda list, bukan grid 7 kolom.
  5. Selesai (opsional) — section/tab event lampau.

4.3 Halaman /events/:slug

  • Cover, judul, deskripsi lengkap, lokasi (link bila ada).
  • Runsheet hari-per-hari dari sessions[] — nama sesi, jam, pemateri.
  • Tombol "Daftar" (hanya bila registration_url ada dan registration_open true).
  • "Tambah ke Google Calendar" (template URL).
  • Tombol Bagikan — Web Share API di mobile, fallback copy link + toast.

4.4 Section Event di landing page

  • Carousel dipertahankan, berubah fungsi jadi teaser: fetch 3–4 event teratas (ongoing dulu, sisanya upcoming).
  • Tombol "Lihat Lainnya" (sudah ada) → link ke /events.
  • Jika API gagal/kosong → tampilkan state kosong rapi, jangan crash.

4.5 Konvensi teknis FE

  • Env: VITE_SGA_CMS_API_URL — daftarkan di src/vite-env.d.ts, set di Cloudflare Pages dashboard (bukan file .env).
  • Pola fetch/cache/loading/error menyalin src/components/reporting/form.tsx (module-level cache, skeleton, unavailable state) — konsisten, nol dependency baru.
  • Kalender custom, responsif; mobile = list agenda.
  • Aksesibilitas: label tombol jelas, kontras cukup, tanggal fokus keyboard.
  • Detail page harus punya meta og:title/og:image per event (via update document.head saat load) — supaya share link di WA menampilkan preview.
